# Оценка проекта LanDrop — glm.md

Дата проверки: 2026-10-24. `./gradlew testDebugUnitTest` — все 12 JVM-тестов проходят.

## Что это

LanDrop — Android-приложение («телефон — папка в Wi-Fi»): фореграунд-сервис
поднимает HTTP-сервер на порту 8080, файлы принимаются из браузера
drag-and-drop'ом, есть веб-галерея телефона, QR-подключение второго телефона,
нативный просмотр и отправка через «Поделиться». ~9.7k строк Kotlin
(прод + 2.3k тестов).

## Сильные стороны

- **Взрослый тестовый охват сетевой части.** Тесты HTTP-сервера, бинарного
  протокола, совместимости с curl и Python-клиентом идут на loopback-сокетах
  без эмулятора — редкость для pet-проектов.
- **Хорошая порезка ответственности.** Сервер / обработчик HTTP / шаблоны
  веба / сохранение файлов / протокол — отдельные файлы, а не god-класс.
- **Осознанные продуктовые решения зафиксированы** в README и `idea.md`
  (нет TLS — по соображениям простоты, нет перезаписи файлов, обрыв = удаление
  недописанного файла).
- **Готовность к магазину**: скриншоты, обложка, тексты карточки, скрипт
  пересборки ассетов.
- README с полноценным HTTP API и описанием бинарного протокола — можно
  интегрироваться без чтения кода.

## Слабые места и риски

1. **Безопасность по умолчанию нулевая.** Любое устройство в Wi-Fi может
   читать, удалять файлы и открытую медиатеку. README честно предупреждает,
   но для апрува Google Play и публичных сетей (кафе, офис) это блокер.
2. **Релиз собирается без оптимизации**: в `build.gradle.kts`
   `release { optimization { enable = false } }` — нет R8/shrinking, APK
   раздут, код легче реверсить.
3. **Вся строковая разметка захардкожена на русском** и в Compose, и в
   HTML-шаблонах (`WebTemplates.kt`, 1678 строк). Английской локализации нет —
   а аудитория Play Store в основном англоязычная.
4. **Живой опрос раз в секунду** (`while (isActive) delay(1000)`) сервера, IP
   и списка файлов. Простой, но неэкономично; для статуса сервиса хватило бы
   broadcast/StateFlow.
5. **`usesCleartextTraffic="true"` глобально** на всё приложение. Интернету
   приложение не нужно — можно ограничить через `networkSecurityConfig`
   (cleartext разрешён только для LAN-адресов/`usesPermittedNetworks`).
6. **Порт жёстко 8080.** Коллизия с другими приложениями/кэш-прокси не
   обработана; выбор порта пользователем или auto-fallback снял бы класс
   жалоб.
7. Нет CI, нет лицензии, namespace `Code_SyS.nas_server` не по конвенции
   (строчные с доменом, например `com.sysys.landrop`) — переименовать можно
   только до первой публикации.

## Идеи по доработке (приоритезировано)

Частично пересекается с бэклогом в `idea.md` (PIN, mDNS, tile, докачка,
тексты — там уже описаны), здесь — с упором на инженерные пробелы.

### P0 — до публикации

- [ ] **PIN/токен для сервера (M).** Опциональный PIN, требуемый в заголовке
  запроса; без него — только страница «сервер закрыт». Закрывает риск №1 и
  вопрос приватности медиатеки.
- [x] **Включить R8 + minify/shrinkResources для release (S).** Сделано: `optimization { enable = true }` в AGP 9 DSL (включает и код, и ресурсы), default-правила платформы применились автоматически. Release-APK 2.9 МБ против 17.8 МБ debug; кастомные keep-права не понадобились.
- [ ] **`networkSecurityConfig` вместо глобального cleartext (S).**
- [ ] **Лицензия (S).** Выбрать (например, MIT или GPLv3) и добавить файл;
  без лицензии форки и публикация юридически серые.
- [ ] **Английская локализация UI (M).** Все строки Compose → `strings.xml`,
  `values-en`; HTML-шаблоны — параметризованные заголовки. Заодно уйдёт
  дублирование ру-строк между экранами.

### P1 — качество и UX

- [ ] **ViewModel + StateFlow вместо секундного polling (M).** Статус
  сервиса, IP и список файлов — вовсе не «каждую секунду меняются»;
  подписка через callback'и сервиса снимет лишнюю работу и упростит
  тесты экранов.
- [ ] **Настройка порта + индикация коллизии (S).** Прописать fail-fast,
  если `ServerSocket(8080)` занят, и дать выбор порта в настройках.
- [ ] **Quick Settings tile (S).** Одна строка с `TileService` — вероятно
  самая частая точка входа после главного экрана.
- [ ] **mDNS-анонс (`landrop.local`) (S/M).** Браузеру не нужно помнить IP;
  заодно открывает путь к авто-обнаружению через `NsdManager` между телефонами.
- [ ] **CI на GitHub Actions (S).** `assembleDebug` + `testDebugUnitTest` на
  каждый PR — тесты уже есть, их просто надо гонять.
- [ ] **Разбить `MainActivity` (886) и `RemoteActivity` (1171) (M).**
  Вынести composables в `ui/`, состояние в ViewModel. Мелочь, но больших
  файлов уже два, и они растут.

### P2 — функциональность

- [ ] **Скачивание с хоста при просмотре с телефона (S).** Кнопка «Сохранить»
  в удалённом окне (есть в `idea.md` #1).
- [ ] **Отмена/повтор передачи в удалённом окне (S/M)**; докачка по
  `Range` — дальше (M/L).
- [ ] **Ограничения загрузки: размер, число соединений, rate limit (S).**
  Дёшево ложится поверх существующего обработчика.
- [ ] **Передача текста/ссылок (+ буфер обмена)** — POST `/text`, история (S).
- [ ] **ZIP при заборе выбранных файлов** — потоковый архив на сервере (M).
- [ ] **Автостоп сервера при простое + использование уже объявленного
  `WAKE_LOCK` только во время передачи (S).**

### Дальний прицел

- TLS с самоподписанным сертификатом, WebDAV/SMB-доступ как к сетевому диску,
  автосинка фото между своими устройствами (см. `idea.md` #14–16).

## Вывод

Проект технически зрелый для скоупа «локальная передача файлов»: серверный
слой протестирован, продуктовая упаковка есть. Главные пробелы —
безопасность по умолчанию и локализация; оба закрываются умеренными
усиливаниями и должны идти до публикации в Play Store.
